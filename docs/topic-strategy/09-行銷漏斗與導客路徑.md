# 09｜行銷漏斗與導客路徑（對接 UT 客服平台）

> **本檔的定位**：把 03–08 的內容產能，接到既有的 UT 客服機器人平台上。
> 設計時已遵守平台既有決定，不要求平台為行銷破例：
> - `E-2 分眾圖文選單不做` → 分眾靠對話關鍵字與問卷，不靠選單
> - `E-7 旅程自動化不開發送，只排入＋預演` → 所有培育動作設計成「排入清單 → 真人執行」
> - `E-8 行銷區塊只放短網址成效、問卷報名兩個入口` → 歸因骨架完全建在短網址上
> - `明確不做：自動外發 AI 行銷` → 沒有任何自動推播設計
> - 紅燈自檢：本檔每一節都標註對應的北極星編號

## 一、先認清現況：平台不是壞了，是沒有人進來

| 事實 | 來源 | 意義 |
|---|---|---|
| 最後一筆真顧客對話 2026-09-16，09-17／09-18 皆 0 | 平台現況報告 | 入口是通的，但沒有需求流進來 |
| 網頁客服入口自測 200、AI 有回覆 | 同上 | 承接能力存在 |
| 旅程四個品牌都是「0 人符合」 | 同上 | 不是旅程邏輯有問題，是池子裡沒有人 |
| 行銷入口只有短網址與問卷兩個 | `E-8` | 歸因鏈路乾淨，但需要有內容來產生短網址 |

> **結論**：零流量的根因是需求端，不是工程端。
> 內容種草（03–07）與品牌滲透（08）是這個平台唯一的燃料來源。
> 這也代表：**在有流量之前，不需要為行銷新增任何平台功能**（符合「最小編碼」）。

## 三、歸因骨架：把一切建在短網址上（N5）

因為 `E-8` 只開了短網址與問卷兩個行銷入口，歸因鏈路必須全部走短網址。

### 3.1 短網址命名規則（建議，供 Wilson 裁定）

```
格式：<軌><內容編號>-<平台>-<版本>
範例：
  T1-A0103-threads-a    軌1 / 話題A1-03 / Threads / A版標題
  T2-A0213-line-a       軌2 / 話題A2-13 / LINE社群 / A版
  T3-PARTNER-fb-a       軌3 / 經銷招募 / FB / A版
  T0-A0601-linkedin-a   軌0 / 話題A6-01 / LinkedIn / A版
```

**規則**
1. **一篇內容一支短網址**，同一篇發不同平台各開一支（否則分不出哪個平台有效）
2. 同一篇的 A/B 標題各開一支
3. 短網址一經發布**不重用、不改指向**（改指向會讓歷史數據失真）
4. 命名一律小寫、用 `-` 分隔、不含中文

### 3.2 一條完整的可追鏈路

```
Threads 貼文（B1-02）
  → 短網址 T1-A0102-threads-a
    → 落地頁（網站文章或 LINE 加好友）
      → members 建立/更新（品牌、通道、userId）
        → 對話發生 → decision_state 每輪寫入
          → lead_maturity 升級
            → handoff_readiness 達標 → 人工接手
              → 電話/Email 收口
```
**這條鏈路上每一段都已經有平台零件，不需要新功能。**
唯一需要補的是「短網址命名紀律」與「decision_state 的判定契約」（見 `10`）。

## 四、軌 1（家屬 B2C）的導客路徑

### 4.1 心智階梯 × 內容 × 落點（承 08 的 S1–S5）

| 階 | 內容層級 | 落地頁該做的唯一一件事 | 不該做的事 |
|---|---|---|---|
| S1 無意識 | L0 議題 | 讓他讀完（不放任何表單） | 放購買連結 |
| S2 問題意識 | L0–L1 | 提供**可下載工具**換取加 LINE | 要他留電話 |
| S3 方案探索 | L1 品類教育 | 引導看比較內容 | 講規格 |
| S4 方案比較 | L2 比較 | 提供「買之前該問的 10 個問題」 | 逼單 |
| S5 決策取得 | L2–L3 | 給補助查詢路徑＋客服入口 | 只給購買頁 |

### 4.2 三個收口出口（依你提供的現況：網站連結、電話、Email）

| 出口 | 什麼時候用 | 文案 |
|---|---|---|
| **網站連結** | 所有內容的預設收口 | 「我把整理好的資料放在這裡」 |
| **LINE／網頁客服** | 需要問到「他家的情況」才能回答時 | 「你家的狀況我不確定，可以跟我說說看」 |
| **電話** | 情緒濃度高、或補助流程需要引導時 | 「這件事用講的比較快」 |
| **Email** | 軌 2／軌 3／軌 0 的資料包交付 | 「我把完整資料寄給你」 |

> **紀律：不在 S1–S3 的內容裡放電話。**
> 太早給電話會得到大量「只是好奇」的來電，消耗客服並污染 lead 數據。

## 五、軌 3（經銷商／代理商）：本案新增的最高槓桿線

### 5.1 為什麼這條線的 ROI 最高
- 一個代理商 = 一批既有的長照客戶關係 + 一批業務人力
- 他們同時是軌 2（專業人員）與軌 1（家屬）的接觸點
- 他們的決策速度比機構採購快（看毛利與好不好賣）

### 5.2 代理商關心的五件事（內容就寫這五件）
| # | 他的真實問題 | 對應內容 |
|---|---|---|
| 1 | 這東西好不好賣？ | 市場數據、走失議題熱度、補助帶來的需求 |
| 2 | 我要怎麼跟客人解釋？ | **銷售話術包**（含「非即時追蹤」怎麼講） |
| 3 | 客人會問的問題我答得出來嗎？ | 標準 FAQ 與反對意見手冊 |
| 4 | 有沒有政府資格可以背書？ | EI05 登錄、NCC 編號的查證教學 |
| 5 | 分潤與支援條件？ | 合作方案（由業務端提供，不在內容公開） |

### 5.3 招募漏斗
```
內容（軌1/軌2 的公開內容，代理商自己會看到）
  → 短網址 T3-*
    → 「合作洽談」問卷（E-8 允許的 forms 入口）
      → 欄位：公司/通路型態/現有客群/區域/為什麼想代理
        → 人工電話
          → 提供銷售話術包（有價值的交付物，而非合約）
```
**關鍵設計：先給話術包，再談合約。** 願意讀完話術包的人，才是真的會賣的人。

## 六、軌 2（專業人員）：B2B2C 的核心

### 6.1 他們不看廣告，他們看三種東西
1. **法規與給付的正確資訊**（誰整理得清楚就信誰）
2. **同業在做什麼**（研討會、產業媒體、社群）
3. **評估與配適的實務細節**（能不能放進照顧計畫、怎麼教家屬用）

### 6.2 專業人員資料包（一份交付物，換一個 Email）
```
內容：
  1. 產品一頁規格（含成熟度標示、認證編號）
  2. EI05 給付碼與申請流程對照
  3. 配適與教學指引（S/M/L、22-28cm、修剪方式）
  4. 家屬常問的 10 題與標準回答
  5. 不適合的個案類型（誠實寫出來）
  6. 同意書與隱私告知範本
```
> 第 5 項是這份資料包的靈魂。**寫出「什麼情況不要推薦我們」的廠商，才會被專業人員記住。**

## 七、軌 0（B2B 場域）：慢線，但單價最高

```
產業媒體/LinkedIn 內容（A5-A8）
  → 短網址 T0-*
    → 方法論長文（不是產品頁）
      → 「場勘準備清單」下載（forms）
        → Email 交付 + 一通電話
          → 場勘預約
            → 單區試點
```
**紀律**：內容一律標示成熟度（現行服務／可延伸／需 PoC）。
B2B 客戶最恨的是「來了才發現要 PoC」，提前講反而加分（見 `06`）。

## 八、漏斗指標（N5；待有流量後才有意義）

| 層 | 指標 | 資料來源 | 現在能不能量 |
|---|---|---|---|
| 曝光 | 各平台觸及 | 平台後台 | 可 |
| 點擊 | 短網址點擊數 | 後台短網址成效（E-8） | **可，已存在** |
| 進入 | 新 members 數（依通道分） | members 表（R-7） | 可 |
| 對話 | 有效對話段數 | 對話紀錄 | 可（注意排除 staff／自測，見 M-8） |
| 成熟 | lead_maturity 分布 | decision_state | **需先定契約（見 10）** |
| 交接 | handoff 次數與回應時間 | 工單 | 可 |
| 收口 | 電話/Email/表單完成數 | forms + 人工登錄 | 部分 |

> **建議的第一個目標不是轉換率，是「讓今天的對話段數不再是 0」。**
> 在樣本數達到統計意義之前，不要計算轉換率 —— 這符合平台紀律中「小母體的答案比較乾淨」（D-10）的警示。
